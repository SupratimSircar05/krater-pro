# Storyboard and evidence intent

| Scene | Visual | Evidence purpose |
|---|---|---|
| 01 — Title | Generated Krater Pro title card | Establishes read-only, sanitized scope. |
| 02 — Live symptom | Identity-redacted comparison-environment Space Manager capture | Illustrates the location-context symptom family. Explicitly not treated as target-monitor evidence. |
| 03 — Monitor overview | Identifier-redacted target-monitor dashboard capture | Establishes current active incident, 0/5 section health, and complete hierarchy sweep. |
| 04 — Pattern | Enlarged section matrix from the same monitor capture | Correlates location-state failures against successful requests, an exact API/UI count, and WebSocket evidence. |
| 05 — Authentic diagnosis | Private-path-free crop of the corrected Krater right pane plus its High-stakes trust state | Shows the real evidence-supported root-cause result without the sidebar, earlier content, path, or project identity. |
| 06 — Authentic remediation | Second identifier-free excerpt from the same corrected Krater result | Shows the real narrow product fix and epistemic label; the following generated proof scene summarizes the target-neutral recheck. |
| 07 — Proof | Generated acceptance-contract card | States the existing local baseline and the live recheck required after repair. |
| 08 — Result | Generated conclusion card | Summarizes the bounded diagnostic outcome. |

## Editorial rules

- No credential, cookie, authorization header, or raw authentication state may appear.
- The comparison capture is never presented as the targeted monitor.
- “Root cause” is qualified as the most evidence-supported inference.
- Causal or formally verified language is prohibited until controlled source instrumentation changes the outcome as predicted.
- Existing automated tests establish monitor/dashboard baseline integrity only; they do not prove the production incident is fixed.
- The demo may be shared as an edited screen demo, not described as an uninterrupted raw session capture.
